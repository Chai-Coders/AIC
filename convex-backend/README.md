# AIC Convex backend

The backend for the AIC website (`frontend/`) and CMS (`cms_gui/`). It replaces
the old Django + Neon Postgres + Cloudinary backend. The homepage background
video stays on Mux.

Convex keeps the database, file storage and server code together. There is no
SQL or migration folder: the tables are declared in `convex/schema.ts` and the
backend logic is the TypeScript in `convex/`, which `npx convex dev` or
`npx convex deploy` uploads to a running Convex server. The server itself is
the Docker image in `docker-compose.yml`.

## Files

| Path | What it does |
|---|---|
| `convex/schema.ts` | Tables: gallery, startups, news, team members, background video, website text, pictures, Mux uploads, sign-in |
| `convex/content.ts` | Public read API. `siteContent` returns everything the website shows in one call |
| `convex/gallery.ts`, `startups.ts`, `news.ts`, `team.ts` | Create / edit / delete, CMS admins only |
| `convex/siteText.ts` | Publishes website text edited in the CMS's Site text page (the texts themselves are listed in `frontend/src/content/registry.js`) |
| `convex/images.ts` | Picture uploads (stored as WebP copies at several widths) and a daily cleanup of unused ones |
| `convex/http.ts` | Serves pictures at `/img/<id>?w=<width>` and the sign-in routes |
| `convex/mux.ts` | Background video uploads to Mux |
| `convex/auth.ts`, `auth.config.ts`, `users.ts`, `lib/access.ts` | CMS sign-in (email + password, no public sign-up) |
| `convex/admin.ts` | Create admins and change passwords from the command line |
| `convex/crons.ts` | Scheduled jobs |
| `convex/migrate.ts`, `scripts/migrate-from-django.mjs` | One-time import from the old Django API |
| `scripts/setup-auth-keys.mjs` | Creates the sign-in signing keys for a deployment |
| `convex/_generated/` | Generated by the Convex CLI; do not edit |

## Local development

No Convex account or Docker needed: the CLI downloads and runs a local backend.

```sh
cd convex-backend
npm install
npx convex dev                     # pick "local deployment"; keeps running and redeploys on save
```

It writes `CONVEX_URL` (API, port 3212 by default) and `CONVEX_SITE_URL` (pictures and
sign-in, port 3213) to `.env.local`. Then, in another terminal:

```sh
node scripts/setup-auth-keys.mjs http://localhost:5175       # the CMS address
npx convex run admin:createAdmin '{"email":"you@example.com","password":"at-least-10-chars"}'
```

Start the apps against it (`.env.example` in each folder lists the variables):

```sh
cd frontend && VITE_CONVEX_URL=http://127.0.0.1:3212 VITE_CMS_URL=http://localhost:5175 npm run dev -- --port 5174
cd cms_gui  && VITE_CONVEX_URL=http://127.0.0.1:3212 VITE_SITE_URL=http://localhost:5174 npm run dev -- --port 5175
```

To fill it with the real content, run the import below with `DJANGO_API_BASE`.

`npm run typecheck` checks the functions without deploying.

## Self-hosting

On the server, next to `docker-compose.yml`:

```sh
cp .env.example .env               # set CONVEX_CLOUD_ORIGIN / CONVEX_SITE_ORIGIN to the public HTTPS addresses
docker compose up -d
docker compose exec backend ./generate_admin_key.sh
```

Put a reverse proxy with HTTPS in front of port 3210 (API) and port 3211 (pictures and
sign-in). The dashboard (port 6791) is bound to localhost only; reach it over SSH
(`ssh -L 6791:localhost:6791 server`) and sign in with the admin key.

Then, from any machine with this repo, put the server's address and admin key in
`convex-backend/.env.local`:

```sh
CONVEX_SELF_HOSTED_URL=https://api.example.com
CONVEX_SELF_HOSTED_ADMIN_KEY=<key from generate_admin_key.sh>
```

and deploy:

```sh
npx convex deploy                                   # uploads schema + functions
node scripts/setup-auth-keys.mjs https://cms.example.com   # once; re-running signs every admin out
npx convex env set MUX_TOKEN_ID <id>
npx convex env set MUX_TOKEN_SECRET <secret>
npx convex run admin:createAdmin '{"email":"…","password":"…","name":"…"}'
```

Build the apps with `VITE_CONVEX_URL` set to the public API address (and `VITE_SITE_URL`
for the CMS).

## Deployment variables

Set with `npx convex env set NAME value`; list with `npx convex env list`.

| Name | Used for |
|---|---|
| `MUX_TOKEN_ID`, `MUX_TOKEN_SECRET` | Uploading background videos from the CMS |
| `JWT_PRIVATE_KEY`, `JWKS` | Signing CMS sessions (set by `scripts/setup-auth-keys.mjs`) |
| `SITE_URL` | The CMS address (set by `scripts/setup-auth-keys.mjs`) |

`CONVEX_SITE_URL` is provided by the server itself (from `CONVEX_SITE_ORIGIN`).

## CMS admins

There is no sign-up page; admins are managed from the command line:

```sh
npx convex run admin:createAdmin '{"email":"…","password":"…","name":"…"}'
npx convex run admin:setPassword '{"email":"…","password":"…"}'
```

To remove an admin, delete their row in the `users` table from the dashboard.

## Importing from Django

`scripts/migrate-from-django.mjs` copies every gallery item, startup, news article,
team member and the background video from the Django REST API, downloading each
picture and storing resized WebP copies. Rows are matched on their Django id, so
it is safe to re-run; it ends by comparing counts.

```sh
DJANGO_API_BASE=https://<django-host>/api node scripts/migrate-from-django.mjs
```

It writes to the server given by the `CONVEX_SELF_HOSTED_URL` and
`CONVEX_SELF_HOSTED_ADMIN_KEY` environment variables (export them in the shell; the
script does not read them from `.env.local`), or to the local dev deployment when they
are not set.
