# AIC Convex backend

The backend for the AIC website (`frontend/`) and CMS (`cms_gui/`). It replaces
the old Django + Neon Postgres + Cloudinary backend. The homepage background
video stays on Mux.

Convex keeps the database, file storage and server code together. There is no
SQL or migration folder: the tables are declared in `convex/schema.ts` and the
backend logic is the TypeScript in `convex/`, which `npx convex dev` or
`npx convex deploy` uploads to a running Convex server. The server itself is
the Docker image in `docker-compose.yml`.

## Files

| Path | What it does |
|---|---|
| `convex/schema.ts` | Tables: gallery, startups, news, team members, background video, website text, pictures, Mux uploads, sign-in, version history, AI drafts and AI sign-ins |
| `convex/lib/registry.ts` | Every editable field with its label and rules. History, the Versions page and the AI tools all read it |
| `convex/lib/history.ts`, `convex/versions.ts` | Version history: every edit is recorded; undo, put back one field, restore to a point |
| `convex/drafts.ts` | The AI draft: proposals, review, approve (all at once, later edits stay on top) and reject |
| `convex/mcp.ts` | The MCP server AI apps connect to, at `/mcp` |
| `convex/oauth.ts` | Sign-in for AI apps (OAuth 2.1 with PKCE), connected apps, test tokens |
| `convex/uploads.ts` | One-time links where the admin drops a picture into the AI draft |
| `convex/content.ts` | Public read API. `siteContent` returns everything the website shows in one call |
| `convex/gallery.ts`, `startups.ts`, `news.ts`, `team.ts` | Create / edit / delete, CMS admins only |
| `convex/siteText.ts` | Publishes website text edited in the CMS's Site text page (the texts themselves are listed in `frontend/src/content/registry.js`) |
| `convex/images.ts` | Picture uploads (stored as WebP copies at several widths) and a daily cleanup of unused ones |
| `convex/http.ts` | Serves pictures at `/img/<id>?w=<width>` and the sign-in routes |
| `convex/mux.ts` | Background video uploads to Mux |
| `convex/auth.ts`, `auth.config.ts`, `users.ts`, `lib/access.ts` | CMS sign-in (email + password, no public sign-up) |
| `convex/admin.ts` | Create admins and change passwords from the command line |
| `convex/crons.ts` | Scheduled jobs |
| `convex/migrate.ts`, `scripts/migrate-from-django.mjs` | One-time import from the old Django API |
| `scripts/setup-auth-keys.mjs` | Creates the sign-in signing keys for a deployment |
| `convex/_generated/` | Generated by the Convex CLI; do not edit |

## Local development

No Convex account or Docker needed: the CLI downloads and runs a local backend.

```sh
cd convex-backend
npm install
npx convex dev                     # pick "local deployment"; keeps running and redeploys on save
```

It writes `CONVEX_URL` (API, port 3212 by default) and `CONVEX_SITE_URL` (pictures and
sign-in, port 3213) to `.env.local`. Then, in another terminal:

```sh
node scripts/setup-auth-keys.mjs http://localhost:5175       # the CMS address
npx convex run admin:createAdmin '{"email":"you@example.com","password":"at-least-10-chars"}'
```

Start the apps against it (`.env.example` in each folder lists the variables):

```sh
cd frontend && VITE_CONVEX_URL=http://127.0.0.1:3212 VITE_CMS_URL=http://localhost:5175 npm run dev -- --port 5174
cd cms_gui  && VITE_CONVEX_URL=http://127.0.0.1:3212 VITE_SITE_URL=http://localhost:5174 npm run dev -- --port 5175
```

To fill it with the real content, run the import below with `DJANGO_API_BASE`.

`npm run typecheck` checks the functions without deploying.

## Self-hosting

On the server, next to `docker-compose.yml`:

```sh
cp .env.example .env               # set CONVEX_CLOUD_ORIGIN / CONVEX_SITE_ORIGIN to the public HTTPS addresses
docker compose up -d
docker compose exec backend ./generate_admin_key.sh
```

Put a reverse proxy with HTTPS in front of port 3210 (API) and port 3211 (pictures and
sign-in). The dashboard (port 6791) is bound to localhost only; reach it over SSH
(`ssh -L 6791:localhost:6791 server`) and sign in with the admin key.

Then, from any machine with this repo, put the server's address and admin key in
`convex-backend/.env.local`:

```sh
CONVEX_SELF_HOSTED_URL=https://api.example.com
CONVEX_SELF_HOSTED_ADMIN_KEY=<key from generate_admin_key.sh>
```

and deploy:

```sh
npx convex deploy                                   # uploads schema + functions
node scripts/setup-auth-keys.mjs https://cms.example.com   # once; re-running signs every admin out
npx convex env set MUX_TOKEN_ID <id>
npx convex env set MUX_TOKEN_SECRET <secret>
npx convex run admin:createAdmin '{"email":"…","password":"…","name":"…"}'
```

Build the apps with these variables (no trailing slashes):

| App | Variable | Value |
|---|---|---|
| `frontend`, `cms_gui` | `VITE_CONVEX_URL` | The public API address |
| `cms_gui` | `VITE_SITE_URL` | The website's address ("View website" links, Site text preview) |
| `frontend` | `VITE_CMS_URL` | The CMS address. Only this address may show the site in the Site text preview |
| `frontend` | `VITE_CONVEX_SITE_URL` | Optional, Vercel only: the backend's site address (`CONVEX_SITE_URL`, serves `/img/`). Turns on CDN caching (below) |

### Caching

- **Convex** caches every query result until the data it reads changes.
- **`GET /content`** (`convex/http.ts`) returns the website's content with cache headers: browsers
  reuse it for a minute, and a CDN keeps it for a minute and then serves the last copy for up to a
  day while it refreshes in the background.
- **Vercel CDN**: with `VITE_CONVEX_SITE_URL` set, `frontend/vercel.ts` rewrites `/content.json` and
  `/media/<id>` on the website's own address to the backend, and Vercel caches them near visitors
  (pictures for a year, as they never change). Visitors then never wait on the backend, and its
  bandwidth stays far inside the free plan. Edits show on the website within about a minute.
- **The website** keeps the last content in the browser (`frontend/src/api/cache.js`) and a copy
  baked in at build time, so pages render before anything is fetched.

The website saves a copy of the content when it is built (`frontend/scripts/snapshot.mjs`)
and shows it until the live content arrives, so rebuild it after large content changes.

## Hosting on Convex Cloud instead

Convex's free plan also works (0.5 GB database, 1 GB files, 1 GB bandwidth a month;
pictures are the main use of bandwidth). There is no server to run:

```sh
npx convex login
npx convex deploy                                   # creates the project the first time
node scripts/setup-auth-keys.mjs https://cms.example.com   # see note below
npx convex run --prod admin:createAdmin '{"email":"…","password":"…","name":"…"}'
```

`setup-auth-keys.mjs` and `npx convex env set` act on the deployment in `.env.local`, which
is the dev deployment after `npx convex dev`; add `--prod` to `npx convex env set` (or set
`CONVEX_DEPLOY_KEY` from the dashboard) to reach production. Use
`https://<name>.convex.cloud` as `VITE_CONVEX_URL`; AI apps connect to
`https://<name>.convex.site/mcp`.

To copy existing data across: `npx convex export --include-file-storage --path data.zip`
on the old deployment, then `npx convex import --prod data.zip`.

## Deployment variables

Set with `npx convex env set NAME value`; list with `npx convex env list`.

| Name | Used for |
|---|---|
| `MUX_TOKEN_ID`, `MUX_TOKEN_SECRET` | Uploading background videos from the CMS |
| `JWT_PRIVATE_KEY`, `JWKS` | Signing CMS sessions (set by `scripts/setup-auth-keys.mjs`) |
| `SITE_URL` | The CMS address (set by `scripts/setup-auth-keys.mjs`). AI apps are sent to `<SITE_URL>/oauth/authorize` to sign in |
| `PUBLIC_SITE_URL` | Optional. The site port's public address for AI apps when it differs from `CONVEX_SITE_URL`, e.g. a test tunnel (see below) |

`CONVEX_SITE_URL` is provided by the server itself (from `CONVEX_SITE_ORIGIN`).

## Version history

Every change to gallery items, startups, news and team members is recorded as it
is saved, in one line of versions (like git without branches). The CMS Versions
page lists them, shows each field before and after, and can undo a version, put
back a single field, or restore the website to how it was after a version. Undo
and restore are saved as new versions, so they can be undone too. CMS edits are
grouped into one version per sitting (30 minutes without an edit by default,
set in Settings → Version history; signing out also ends it).

Pictures that were replaced or deleted are kept while the history mentions
them, so undo can bring them back. The homepage video is not versioned.

## AI connection (MCP)

AI apps (Claude, ChatGPT, Claude Code, Cursor, ...) connect to
`<CONVEX_SITE_URL>/mcp`. They can search and read the site and propose changes,
which collect in one draft that only the admin can approve, on the Versions page.
There is no tool to publish. The CMS's Settings → MCP tab has the address and
step-by-step setup for each app.

The CMS's own **AI Assistant** follows the same rules: once its review agent has
checked a change, it joins that same draft, and nothing goes live until the admin
approves it on the Versions page. Edits made by hand in the CMS go live at once
and are recorded in the same history. All three use the same field rules
(`convex/lib/registry.ts`, `convex/lib/siteText.ts`). See `docs/ai-agent.md`.

For apps on the internet (Claude.ai, ChatGPT) the site port (3211) must be
reachable over **public HTTPS**, and `SITE_URL` must be the CMS address: the
sign-in page AI apps open is `<SITE_URL>/oauth/authorize`. The CMS host must
serve `index.html` for every path (`cms_gui/vercel.json` does this on Vercel).

To test the MCP server without OAuth (MCP Inspector, curl, Claude Code):

```sh
npx convex run oauth:createTestToken '{"email":"<admin email>"}'
claude mcp add --transport http aic-website http://127.0.0.1:3211/mcp --header "Authorization: Bearer <token>"
```

Test tokens last 30 days and appear under "Connected apps", where they can be
disconnected.

### Testing with Claude.ai or ChatGPT before the server is public

Expose the local site port through a temporary HTTPS tunnel and tell the backend
its public address:

```sh
cloudflared tunnel --url http://127.0.0.1:3211      # prints https://<random>.trycloudflare.com
npx convex env set PUBLIC_SITE_URL https://<random>.trycloudflare.com
```

Add `https://<random>.trycloudflare.com/mcp` as a custom connector. The sign-in
page still opens on the local CMS in your browser, which is fine. The address
changes every time the tunnel restarts; afterwards run
`npx convex env remove PUBLIC_SITE_URL`.

## CMS admins

There is no sign-up page; admins are managed from the command line:

```sh
npx convex run admin:createAdmin '{"email":"…","password":"…","name":"…"}'
npx convex run admin:setPassword '{"email":"…","password":"…"}'
```

To remove an admin, delete their row in the `users` table from the dashboard.

## Importing from Django

`scripts/migrate-from-django.mjs` copies every gallery item, startup, news article,
team member and the background video from the Django REST API, downloading each
picture and storing resized WebP copies. Rows are matched on their Django id, so
it is safe to re-run; it ends by comparing counts.

```sh
DJANGO_API_BASE=https://<django-host>/api node scripts/migrate-from-django.mjs
```

It writes to the server given by the `CONVEX_SELF_HOSTED_URL` and
`CONVEX_SELF_HOSTED_ADMIN_KEY` environment variables (export them in the shell; the
script does not read them from `.env.local`), or to the local dev deployment when they
are not set.
